macOS App Classifier
Native Edition

Static analysis + agentic AI classification of macOS .app bundles and Mach-O binaries. Uses only tools that ship with macOS — no brew, no pip, no dependencies.

Zero dependencies macOS 12+ Claude API Ollama local LLM ClickFix detection Packing detection

00 How It Works

The skill runs a 9-phase pipeline. Feature extraction uses native macOS CLI tools. A Claude (or local Ollama) agent then iteratively calls those features as tools, reasons over them, and produces an explainable verdict.

Input .app bundle or Mach-O binary │ ├─ Phase 1 Pre-flight file · xattr · mdls (quarantine, download origin) ├─ Phase 2 Bundle Inventory find · plutil (Info.plist, structure, persistence) ├─ Phase 3 Signature & Trust codesign · spctl · xcrun stapler ├─ Phase 4 Binary Analysis otool · nm · lipo · strings ├─ Phase 5 Risk Aggregation score signals per risk-signals.md ├─ Phase 6 Agentic AI Loop Claude / Ollama tool-use → reasoning chain ├─ Phase 7 Obfuscation Check entropy · UPX sigs · string density · symbol anomalies · run-only AppleScript └─ Output JSON report verdict · confidence · risk_score · reasoning chain

01 Installation

1 — Install the package

# macOS, native pipeline + Claude API — the normal case
pip install "macskillet[claude]"

# Non-macOS host, or bulk cross-platform pipelines
pip install "macskillet[claude,portable]"

# Local inference instead of the API
pip install "macskillet[ollama]"

# On-device Apple Foundation Models (macOS 26+ with Apple Intelligence, Xcode 26+)
pip install "macskillet[apple]"

2 — Set your API key (Claude mode)

export ANTHROPIC_API_KEY="sk-ant-..."

3 — (Optional) Install Xcode CLI tools

Needed for otool, nm, lipo, and xcrun stapler. Most analysts already have these.

xcode-select --install
✓ No further dependencies
All other tools — codesign, spctl, xattr, mdls, plutil, strings, python3 — are pre-installed on every macOS system. The native pipeline itself has zero Python dependencies; feature extraction (--features-only) works on a bare pip install macskillet, no API key needed.

02 Quick Start

Classify a suspicious app in one command:

# Analyze a .app bundle (Claude API)
macskillet /path/to/Suspicious.app --pretty

# Analyze a bare Mach-O binary
macskillet /tmp/helper --pretty

# Save report to file
macskillet /path/to/App.app --pretty -o report.json

03 Single Sample Analysis

App bundle

macskillet /Applications/SomeApp.app
macskillet ~/Downloads/Installer.app --pretty

Bare Mach-O binary

# Common ClickFix drop paths
macskillet /tmp/helper
macskillet /tmp/update
macskillet /private/var/tmp/zad

dylib or framework binary

macskillet /path/to/suspicious.dylib
⚠ Never run the sample
Always analyze on an isolated macOS VM or analysis host. The classifier performs static analysis only and does not execute the sample — but treat all samples as live until classified.

04 Batch Analysis

Process an entire directory of samples and write results as JSONL (one report per line), suitable for ingestion into your 40k-sample dataset pipeline. 

# Classify all Mach-O binaries and .app bundles in a directory
macskillet \
  --batch /path/to/samples/ \
  -o results.jsonl

# With local LLM for faster/cheaper bulk processing
macskillet \
  --batch /path/to/samples/ \
  -o results.jsonl \
  --ollama --model qwen2.5:14b

Each line in results.jsonl is a complete JSON report. Parse with:

# Python: load all reports
import json

reports = []
with open("results.jsonl") as f:
    for line in f:
        reports.append(json.loads(line))

malicious = [r for r in reports if r.get("verdict") == "MALICIOUS"]
print(f"{len(malicious)} / {len(reports)} classified as MALICIOUS")

# Group by ClickFix-style behavioral suspicion (signature_trust override)
suspicious_signed = [r for r in reports
            if r.get("signature_trust", {}).get("trust_level") == "suspicious_signed"]
print(f"Signed samples with revoked trust: {len(suspicious_signed)}")

05 Feature Extraction Only

Extract the full static feature set without running the AI classifier. Useful for building your own ML pipeline on top of the features, or inspecting raw data before handing off to the agent. 

# Extract features, write JSON
macskillet /path/to/App.app \
  --features-only --pretty -o features.json

# Or use the extractor directly
python3 feature_extractor.py -f /path/to/App.app --pretty

# Bulk extraction (fast — no API calls)
python3 feature_extractor.py \
  --dir /path/to/samples/ \
  -o features.jsonl

Then classify separately from cached features:

# Run AI classification against pre-extracted features
python3 agent_loop_local.py --features features.json --model qwen2.5:14b
Tip — decoupled pipeline
For a 40k-sample dataset, extract all features first in one fast pass (no API calls, no rate limits), then run the agent in a second pass. Features are cached as JSON so you can re-classify with different models without re-running extraction.

06 Local LLM via Ollama

Replace the Claude API with a local model for air-gapped environments, privacy-sensitive samples, or bulk processing without per-token costs. The same 13 analysis tools work identically — only the inference backend changes.

☁️

Claude API (default)

Best reasoning quality. Requires ANTHROPIC_API_KEY. Internet required.

macskillet \
  App.app
🖥️

Ollama (local)

Offline, no API key, no data leaves the machine. Requires Ollama running.

macskillet \
  App.app --ollama \
  --model qwen2.5:14b

Setup

# 1. Install Ollama
brew install ollama

# 2. Start the server (keep this running)
ollama serve

# 3. Pull a model
ollama pull qwen2.5:14b    # recommended
ollama pull llama3.1:8b    # faster, lower RAM

# 4. Install macskillet with the Ollama extra (only external dep)
pip install "macskillet[ollama]"

# 5. List what you have
python3 -m macskillet.native.agent_loop_local --list-models

Model Selection by Hardware

HardwareModelSpeedNotes

M2/M3 Pro (32 GB) qwen2.5:14b ~20 tok/s Best quality/speed balance ← recommended

Smaller local models (7–8B) can miss subtle multi-step reasoning that Claude handles well. For high-stakes classification use Claude. For bulk triage or air-gapped work, qwen2.5:14b gives a good balance.

07 ClickFix Detection

ClickFix is the dominant macOS initial access vector in 2025–2026, up 517% year-over-year. There is no dedicated ClickFix detector module — a first version existed but was retired after investigation found most of its own indicator table was structurally unreachable (fed from a separate, narrower pre-filter) and its packer-signature scan duplicated the obfuscation detector's, which is a strict superset. ClickFix indicators are now covered by two general-purpose mechanisms that check the dropped payload binary for static indicators — not the delivery webpage.

Two Delivery Chains

A
Terminal — Classic

Fake support/CAPTCHA page → user pastes base64 -d | bash → curl downloads payload → drops to /tmp/helper → xattr -c strips quarantine → chmod +x → executes

Partly mitigated by macOS 26.4 Terminal paste protection.

B
Script Editor — Newer Evasion

Fake page → applescript:// URL opens Script Editor pre-filled → do shell script fires obfuscated curl | zsh → base64+gzip payload → /tmp/helper → xattr -c → executes

Bypasses the 26.4 Terminal protection. Active as of April 2026.

What Gets Checked, and Where

CategoryExamplesRiskSource
Quarantine tampering xattr -c, com.apple.quarantine HIGH gatekeeper_bypass (common/strings.py)
Shell piping curl | bash, wget | sh HIGH download_execute
Data harvesting key4.db, wallet.dat, keychain paths HIGH browser_data, crypto_wallet, keychain_access
AMOS/Odyssey family markers osalogging, receiveex.php, joinsystem HIGH malware_family_marker
TCC abuse, dev secrets, cloud-C2 tccutil reset, .npmrc, api.telegram.org HIGH/MEDIUM tcc_abuse, dev_secret_harvest, cloud_c2_exfil, cloud_hosting_abuse
Script Editor vector do shell script, applescript:// HIGH automation
Run-only AppleScript payload 0xFADEDEAD marker (source-stripped applet) HIGH applescript_analysis.runonly_applescript

Reading the Result

There's no clickfix_detection field, score, confidence, or delivery-chain label anymore. The classify report's reasoning_chain/key_indicators already narrate this evidence in English; to inspect the raw signals directly, run with --features-only — these fields are all top-level in that output, not nested under each other:

# macskillet App.app --features-only --pretty
{
  "strings_of_interest": [
    {"value": "xattr -c", "category": "gatekeeper_bypass", "risk": "HIGH"}
  ],
  "applescript_analysis": {
    "runonly_applescript": true
  },
  "signature_trust": {
    "trust_level": "suspicious_signed",
    "summary": "developer_id sample exhibits run-only AppleScript or suspicious-string evidence — signing trust credit revoked..."
  }
}
Key signal
A signed/notarized sample that also matches a gatekeeper_bypass, automation, download_execute, cloud_c2_exfil, or malware_family_marker string category — or ships a run-only AppleScript payload — has its trust credit revoked entirely by signature_trust and is relabeled suspicious_signed. This is the "notarized ≠ safe" override.

08 Packing & Obfuscation Detection

Packed binaries defeat static analysis. The detector runs seven complementary checks because no single method is reliable alone.

MethodToolWhat it flags
Packer signatures python3 (bytes) UPX!, MPRESS1, VMProtect magic bytes
Segment entropy otool + python3 __TEXT entropy >7.5 = packed; >7.0 = suspicious
String density strings + python3 <5 strings/KB in a large binary = packed
Symbol anomaly nm Zero symbols in large binary = stripped/packed
Junk code nm >5000 symbols = OSX.Zuru / Cobalt Strike padding
Section names otool -l UPX0, MPRESS1/2 section names
Encryption flag otool -l LC_ENCRYPTION_INFO with cryptid=1
Runtime detection strings Go / Rust / Nim / PyInstaller / Nuitka (adjusts entropy/junk-code scores)
Go / Rust false positive mitigation
Go and Rust binaries are legitimately high-entropy and have low string density due to statically linked runtimes. The detector identifies the runtime and lowers the suspicion score accordingly, avoiding false positives on legitimate dev tools.
Nuitka is treated as a suspicion boost, not a suppression
Nuitka-compiled Python binaries (a real, current macOS malware pattern — e.g. Infiniti Stealer, Mar 2026) are detected via a byte-exact onefile-archive marker and the __compiled__ module attribute string. Unlike Go/Rust/Swift, Nuitka isn't yet a common legitimate macOS distribution target, so detecting it does not suppress the junk-code (symbol-count) heuristic — it adds to suspicion instead, the same way Nim does. Packer-signature detection (including Nuitka/PyInstaller) now also runs on the portable pipeline's main binary and on every Mach-O item --deep analyzes (embedded dylibs/helper binaries), not just the native pipeline's top-level binary.
Run-only AppleScript detection runs on portable too
Run-only/compiled AppleScript detection (the 0xFADEDEAD/FasdUAS markers) against the main binary and its bundle's AppleScript files runs on both pipelines via the shared common/deep_scan.py check, exposed at the same top-level features["applescript_analysis"] field on both.
Entropy/symbol/section obfuscation detection runs on portable too
Entropy-ratio packing detection, symbol-table anomaly detection, section-name anomaly detection, string-density scoring, Go/Rust/Swift/Nim/Nuitka runtime-marker detection, and LC_ENCRYPTION_INFO detection all run on the portable pipeline now, populating features["obfuscation"] there for the first time. Native gathers the raw data via otool/nm/strings; portable gathers the same raw data via LIEF and common/strings.py::read_strings(). Both feed the exact same scoring formulas and thresholds in common/obfuscation_signals.py, so a threshold can never drift between pipelines.
Base64 strings are decoded, not just shape-matched
A validated base64 string is decoded and classified further when a stronger sub-signal is present: encoded_python_bytecode (HIGH — structural .pyc magic-number shape), encoded_compressed_payload (MEDIUM — gzip/zip/zstd magic bytes, a nested "Matryoshka" encoding layer), or encoded_script (MEDIUM — shebang line). A base64 string matching none of these still reports the generic possible_base64/LOW finding, unchanged.

Reading the Result

09 Output Format

Every report is a JSON object. Top-level fields:

verdict
MALICIOUS  SUSPICIOUS  BENIGN
confidence
HIGH / MEDIUM / LOW — how certain the agent is
risk_score
Integer 0–20+. <3 = benign, 6–8 = suspicious, 13+ = malicious
recommendation
BLOCK / INVESTIGATE / ALLOW
summary
2–4 sentence human-readable explanation of the verdict
key_indicators
Ordered list of top signals that drove the verdict
reasoning_chain
Step-by-step analysis: observation → inference → risk_delta per step
obfuscation_detection
Packing/obfuscation result: techniques detected, entropy analysis, packer signatures, run-only AppleScript
deep_scan
Only present with --deep/--deep-limit: static analysis of up to N embedded bundle items beyond the main executable (AppleScript files first, then dylibs, then other Mach-O binaries). enabled, limit, scanned (each entry: path, kind, analysis), skipped_count, skipped_by_kind, summary. Feeds signature_trust's trust-revocation gate the same way the main binary's own findings do.
agent_tool_calls
Full log of every tool the agent called, with inputs and outputs (audit trail)
inference_backend
claude or ollama/model-name

11 Quick Triage (Bash Only)

For incident response when you can't run Python or need a fast human-readable summary, use quick_risk.sh. No Python required, no API calls — just bash and native macOS tools. 

# Run triage script
bash quick_risk.sh /path/to/Suspicious.app

# Or specify binary explicitly
bash quick_risk.sh /path/to/App.app /path/to/App.app/Contents/MacOS/AppBinary

The script checks (in order): file type, extended attributes, code signature, Gatekeeper, notarization, entitlements, architectures, dylibs, high-risk symbols, injection triad, suspicious ObjC classes, suspicious strings, and bundle anomalies.

5-second one-liner
T="/path/to/App.app"; B="$T/Contents/MacOS/$(plutil -extract CFBundleExecutable raw $T/Contents/Info.plist)"
echo "--- Sig ---" && codesign --verify -v "$T" 2>&1 | tail -2
echo "--- Gate ---" && spctl --assess -v "$T" 2>&1
echo "--- Risky ---" && nm -u "$B" 2>/dev/null | grep -E "mach_vm|task_for_pid|dlopen|system$|SecKeychain"

12 FAQ

Does this work on Linux or Windows?

The native backend doesn't — it wraps codesign, spctl, xattr, and other Apple-specific tools, so it requires macOS. For cross-platform analysis, pass --backend portable: the same macskillet CLI switches to the LIEF/machopy-based backend, which works on any OS. See Agent Tools Reference and docs/architecture.md for what differs between the two.

Can I analyze App Store apps?

Yes, but LC_ENCRYPTION_INFO with cryptid=1 means the binary is DRM-encrypted. Static analysis of the encrypted binary is limited — you'll still get signature, entitlements, dylib list, and metadata, but symbol and string analysis will be severely limited until the binary is decrypted.

Why does a Go/Rust binary score as suspicious?

Go and Rust embed their entire runtime statically, which produces high entropy and low string density — the same signals as a packed binary. The detector identifies the language runtime (via Go build ID: or __rustc strings) and automatically reduces the suspicion score to avoid false positives.

The agent used only 4 tool calls — is that enough?

It depends. For a clearly benign or clearly malicious sample, the agent will often reach a high-confidence verdict after 4–6 calls. For ambiguous samples it may use 10–12. The agent stops when it has sufficient evidence — unnecessary tool calls are avoided to keep latency down.

How do I add my own ClickFix-style indicators?

There's no dedicated ClickFix detector — add a StringPattern entry to SUSPICIOUS_PATTERNS in common/strings.py, the single source of truth for suspicious-string detection shared by both the native and portable pipelines. Each entry has a category, regex pattern, risk level, and description. If the new category should also revoke trust for signed samples (like gatekeeper_bypass or automation do today), add it to _SUSPICIOUS_CATEGORIES in common/signature_trust.py too.

Should I use the native or portable backend?

They're two backends of the same tool, not separate skills — backends.py picks native on macOS and portable elsewhere, or force either with --backend. Use native for live incident-response triage on macOS (it has extra signals: quarantine xattr, Gatekeeper verdict, notarization staple, ObjC class/method names). Use portable for bulk cross-platform pipeline work. You can extract features with both and merge the JSON outputs if you want both signal sets for the same sample.
